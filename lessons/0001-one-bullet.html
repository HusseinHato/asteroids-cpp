Asteroids / C++ / Lesson 01

Give one bullet a shape

Your win: draw one stationary white dot using your own Bullet class. Movement and shooting come later. Keep Ship open as a worked example.

C++ glossary

1. Understand the pieces

A class describes a type; an object is one instance. Ship is a class; Game's m_ship is an object. Each Bullet object will contain its own shape, velocity, and lifetime.

The header describes what callers can use. The source file contains function bodies. A constructor runs when an object is created; it has no return type.

Bullet::Bullet(sf::Vector2f position, sf::Vector2f velocity)
    : m_velocity(velocity) {
    // Set up the shape and starting position here.
}

Bullet:: says this definition belongs to Bullet. The two parameters are input values. : m_velocity(velocity) initializes the member from the parameter before entering the body. The m_ prefix is this project's naming convention, not C++ syntax.

Like Ship, inherit from sf::Drawable to support window.draw(bullet) and sf::Transformable to get position methods. Your private drawing override tells SFML how to draw the circle. override lets the compiler catch a mismatched signature. See the SFML Drawable reference.

2. Predict before coding

A radius-3 circle has local bounds from 0 to 6 on each axis. What origin would make its position refer to its center?

Check your prediction

(3, 3). Setting the origin there makes the shape centered on the bullet's position. With the default origin, that position refers to the upper-left corner of its local bounds.

3. Your code

  1. Create src/Bullet.hpp. Use #pragma once, include SFML graphics, and declare Bullet with the same two base classes as Ship.
  2. Declare a public constructor taking position and velocity, both sf::Vector2f. Declare void update(sf::Time dt); and bool isExpired() const;. We will define those two methods in lesson 2; do not call them yet.
  3. Add private members: sf::CircleShape m_shape;, sf::Vector2f m_velocity;, and sf::Time m_remainingLifetime{sf::seconds(1.f)};. The braces initialize the lifetime. Add the same private draw declaration as Ship.
  4. Add constexpr float BULLET_RADIUS = 3.f; inside Config. In src/Bullet.cpp, include Bullet.hpp and Config.hpp. Define the constructor: initialize velocity, set the circle's radius, set its origin to (radius, radius), set its fill to white, and set the Bullet object's position from the position parameter.
  5. Define the drawing override following Ship: combine states.transform with getTransform(), then draw m_shape with those states. This applies the Bullet's position to the circle; do not also set the circle's position to the world position.
  6. Add src/Bullet.cpp to the existing CMake executable source list.
  7. For this temporary checkpoint, include Bullet.hpp in Game.hpp and add Bullet m_bullet{{200.f, 200.f}, {0.f, 0.f}}; beside m_ship. These two pairs supply position and velocity to the constructor. Draw m_bullet inside Game::render, after the ship and before display.

The lifetime literal becomes a Config constant when we implement lifetime behavior. This temporary single bullet will be replaced by the collection in lesson 3.

4. Build and inspect

From the repository root, using the existing configured build:

cmake --build build
.\build\Asteroids.exe

Expected: the ship still moves and a small white dot stays centered at (200, 200). Do not call Bullet::update yet. Declaring a non-virtual method without defining it is fine until it is used.

If it fails, use the error as a clue
  • “Undefined reference” to the constructor: check the source was added to CMake and that the definition matches the declaration.
  • “Abstract type”: check your draw signature against Ship, including the trailing const.
  • Dot at the top-left: check setPosition and the transform combination in draw.
  • No dot: check radius, fill color, and that drawing happens between clear and display.
